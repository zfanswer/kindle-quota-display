# 电源与无线行为

## 统一省电循环

```text
开无线 → 最多30秒联网窗口 → 下载/绘图成功或本轮失败
→ 选择等待 → 关无线 → RTC mem休眠 → 到期后下一轮
```

| 本轮结果 | 下一等待 |
| --- | --- |
| 成功绘图并提交有效PNG | INTERVAL，默认3分钟；连续失败清零 |
| 第1、2、3、4次连续失败 | 3、6、9、12分钟 |
| 第5次及后续连续失败 | 15分钟 |

白天、夜间和外出均使用同一规则。计数按完整轮次，不按请求；有效“暂无数据”PNG算成功。正常离线保留旧图和采样时间，不重复重画。等待从当轮工作后计算，两个尝试之间还包括网络/绘图开销。

自动只探测缓存、配置IP、主机名，每次候选去重，最多3次短探测，绝不扫描子网。更换网络、DHCP换IP且主机名失效时，点击“重找额度服务器”。同网至少一个已知地址有效时，长时间离线后自动恢复最多额外等待15分钟再加工作开销；不做早上加速的特殊规则。手动操作跳过等待。

每轮Wi-Fi重新连接仍是主动省电行为。调用系统无线开关；[Amazon Paperwhite手册](https://kindle.s3.amazonaws.com/UserGuide/Paperwhite_V2/Kindle_Paperwhite_V2_UserGuide_US.pdf)将关闭无线与飞行模式对应，界面图标可能变化。是否真正挂起、具体功耗收益须按固件实测。

## 网络预算

自动共用30秒，手动120秒，覆盖无线就绪、DNS/health、PNG和在线遥测。开启无线后轮询有效IPv4，再做有限的已知地址短重试；IP存在不保证路由/AP连接或服务器健康。每个请求的超时不超过剩余预算，外层watchdog也约束wget/DNS，手动扫描最多90秒、16并发。超时/停止回收拥有的命令，终止有最多1秒强制回收宽限。

FBInk最多10秒，设备属性命令最多3秒，sync最多10秒，均属于网络窗口外短工作；30秒不是总清醒时间硬上限。服务器不可达时不POST诊断，不因失败全网扫描。

## 早醒与停止

RTC设置显式正数等待，按所选RTC的since_epoch与alarm截止时间计算剩余，不拿硬件RTC绝对epoch与系统钟比较。墙钟校时不会把15分钟等待拉长。

提前返回先判断停止和手动请求；无待办时恢复屏保保护、按需重画缓存，无线保持关闭，最多20秒短交互后重新RTC挂起剩余时间。不会开着Wi-Fi sleep 900，也不增加网络失败数。停止入口可以中断短等待/探测；电源键不是停止指令。

存在明确保护例外：60秒内连续3次挂起仅持续0–2秒，或挂起失败/RTC时间异常，记suspend_failed后退出、恢复原无线和屏保管理，可能回到原生待机页。普通单次早醒继续任务。alarm被其他任务替换时不清除它。

手动重找由活动worker处理请求，跳过当前退避；Library操作先使设备醒来，信号不能单独唤醒mem。没有worker时只发现并刷新一次，不擅自启动自动循环。

## 配置、诊断与验收

模板ALLOW_SUSPEND=0；bootstrap的设备能力检查通过后改为1并启动。Mac离线不会阻止启动进入退避。已有任务只恢复缓存画面。直接调用run且ALLOW_SUSPEND=0是诊断模式，普通等待保持无线；主入口没有独立常开模式。

lifecycle.log保存固定事件，power.log每轮记录failures/next_delay/cycles；每个最多保留两份约256KiB。休眠返回、停止、离线通常只记本地；在线且预算有余才POST，因此服务器history不能证明每次RTC返回。run.log每轮达到256KiB时轮换，避免长时间失败输出无界增长。

离线测试验证算法、超时、锁和恢复；Host HTTP验证服务；frame_ok仅是设备自报。新版需实测30秒就绪预算、RTC剩余重挂起、手动重找、停止恢复及至少一小时连续运行。夜间电量比较须控制前光、起始电量及观察时长，记录真实RTC/无线开启时长；测试减少探测次数不能直接换算电量百分比。
